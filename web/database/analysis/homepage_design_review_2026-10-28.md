# 首页设计复盘：Codex 原型与用户提供的 Claude 示例

日期：2026-10-28。

## 比较范围与证据

比较本地 `index-concept-a.html`、`index-concept-b.html`、`css/index-concepts.css`、`index-concept-c.html`、`css/index-studio.css` 与用户提供的 `index_classic.html`，以及用户明确给出的审美规范。

本次为源代码、文案与结构审阅，未完成浏览器截图对照。此前本地 HTTP 预览受到环境网络限制，不能把打开请求已排队当作已完成视觉检查。结论不冒充实际渲染测量。

## 核心判断

我的主要不足是没有把“数学家自用的工具集”和“减少分心”转成稳定的设计约束。A/B 把书页感简化成暖底、Georgia、大留白；C 在被否定后又转向常见产品展示组件。变化的是表面样式，缺少稳定的内容与视觉逻辑。

不能用这次案例推断两个模型的一般能力高低；可以明确判断，我交付的这些版本与这位用户的目标不匹配。新提供的完整规范并非先前已知条件，不能倒推为我明知故犯；但学术工具、Workspace 优先、少分心、少文字这些目标先前已经明确。

## Claude 示例仍需检查的地方

1. **旧版入口自循环。** 当前文件名就是 `index_classic.html`，页眉、故障提示和底部 Classic index 均链接到这个文件。真实旧首页仍在 `index.html`。正式使用前必须规划迁移，不能只检查路径存在。
2. **渐隐作用在整个 hero。** `.hero` 的 `mask-image` 施加到整个元素，包括文字、链接、SVG。若意图仅让网格渐隐，应将背景移到独立伪元素，否则下部内容可能变淡，尤其需检查单列布局。
3. **仍可精简。** 首屏说明较长，页眉也包含 Classic index；不完全等同于“只有主入口突出、其他一切安静”。减少文字仍应以用户反馈为准。
4. **数学算子与变量未完全区分。** `.mock .m` 没有统一区分变量斜体与算子正体。规范中的 `det` 斜体建议也应按数学排版惯例细化。
5. **SVG 的最小文字。** SVG 内存在 11px 的源字号，随 viewBox 缩放还会缩小，需实际检查窄屏可读性。字体外链加载、正文对比度与暗色主题也需验证。
6. **措辞需核实。** “A tutorial is being written” 比用户确认的“未来需要但未完成”更强；“Everything runs in your browser” 也不能未经核实扩大到所有工具和联网功能。

数学例子的人工核对：λ=(4,2,1) 的钩长为 6、4、2、1、3、1、1，乘积 144，7!/144=35；P² 上 O(1) 的 Euler 特征为 3；矩阵 [[1,2],[3,4]] 的行列式为 −2；A₄ 有 10 个正根。这些例子能在解释产品的同时建立数学可信度。

## 工作流程的改进

1. 开始前把用户已确认的定位、主行动、禁用项整理为约束；不靠不断换视觉风格猜喜好。
2. 阅读真实 Workspace 的 Assets 与面板结构，用准确内容形成视觉重点。
3. 先做一个结构正确的版本；需要比较时改变一个明确变量，并用实际页面或截图比较，而不是让用户从形容词想象页面。
4. 使用语义设计变量与可维护源码，把色彩、字体、描边和状态统一起来。
5. 在交付前检查真实渲染、数学内容、字号与对比度、键盘焦点、主题、窄屏，以及链接的语义目的。不能把“文件存在”当成“退路有效”。
6. 验证条件不足就直说未验证，不再用“精致”“耐看”等判断为未经查看的输出背书。
