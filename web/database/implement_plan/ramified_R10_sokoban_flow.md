## 3. 已实施的流程与存档规则

```text
开始游戏 → 游戏列表 → 推箱子 → 数字选关 → 进入关卡
通关 → 下一关，或选择关卡
游戏菜单 → 选择关卡
```

| 情况 | 行为 |
| --- | --- |
| 第一次进入 | 19 个数字按钮，前 3 关可选；其余显示锁定并禁用。 |
| 选择已解锁关卡 | 直接进入原棋盘，不经过对局准备页。有尚未完成的旧存档时沿用替换确认。 |
| 不同关卡首次通关 | 记录已通关 ID，并开放编号最小的未解锁关；顺序不限于 1、2、3。 |
| 重复通关、撤销后重做 | 保留完成记录，不再次增加解锁。R 键重开也不清除长期进度。 |
| 下一关 | 当前编号加一。例如第 2 关首次完成后解锁第 4 关，下一关仍进入第 3 关。已完成棋局不再多加一次替换确认。 |
| 最后一个编号完成 | 仅显示“选择关卡”；全部 19 关都有完成记录时才显示“全部关卡已通关”。 |
| 刷新／更换游戏 | 整个游戏集仍保留一份当前棋局；已解锁和已通关记录独立保存，不被其他游戏覆盖。 |
| 返回／取消／加载失败 | 保留原局、撤销历史和存档。失败可重试或返回；退出后迟到的加载响应不能重开选关页或替换棋局。 |
| 浏览器无法保存 | 本标签页内继续记录解锁，并在菜单提示保存失败；不假装已持久保存。 |

长期记录使用 `ramified.minigames.sokoban.progress.v1`，按稳定 ID 保存 `unlocked`、`completed`；当前棋局仍使用原版本 1 存档，仅增加可选的官方关卡 ID。无该标记的旧存档和调试导入仍可恢复游玩，但不会冒充官方关卡完成记录。archive/debug 不执行玩家关卡解锁。

选关沿用完整游戏内页面、黑底白字标题和固定 4:3 外框；数字网格在桌面／全屏居中，窄屏在页内滚动。通关复用现有结束提示，已修复展开方向控件遮住窄屏结果按钮的问题。没有新增美术、星级、奖励或自动跳关。

验收时发现并修复两个相关问题：取消准备会重新生成状态文字并改写存档；推箱子撤销记录错误地包含即将开始的移动会话，导致撤销后一直判为移动中。现在取消恢复原状态文字，撤销保存移动开始前的空闲状态。

## 4. 目录迁移及维护入口

- `ramified_minigame_presets/presets.js`：统一索引和唯一关卡顺序来源，19 个 `file` 改为子目录路径。
- `js/ramified_minigames_sokoban_progress.js`：长期记录、去重、解锁与存储失败处理。
- `js/ramified_minigames_player.js`：数字选关、加载／取消、新局确认及下一关路由。
- `js/ramified_minigames_setup.js`：精确加载所选关卡、官方 ID 随游戏／存档保留、原通关提示适配。
- `js/mosaic_calculator.js`：推箱子导出提示和索引条目使用子目录，导入再导出保留该位置；其他游戏位置不变。
- 工作台构建器递归收集预设子目录，并通过 `node js/build_math_workspace_native_editors.mjs` 更新当前 v8 及工作台资源，没有手改历史版本。
- 新玩家文案及无障碍标签提供中英文，玩家／archive／计算器受影响资源缓存已更新。
