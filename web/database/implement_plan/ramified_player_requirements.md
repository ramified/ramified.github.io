## 3. 后续修改必须保留的约束

- 保留固定 4:3 外框及浏览器全屏能力。
- 玩家菜单与设置占满外框；限制复杂内容的阅读宽度时，不重新形成独立小面板。
- 保留黑底白字标题栏，以及主菜单／游戏菜单按钮居中。
- 复用原棋盘渲染、棋子、游戏专用控件和交互，不因菜单工作重做美术。
- 不修改玩法、边界粘合表现，不新增宣传文案、动画或额外游戏系统。
- 新增和直接修改的玩家界面必须同时支持英文、简体中文，并遵循 [i18n 原则](ramified_i18n_principles.md)。
- 建议必须与用户已明确的要求分开记录。未决定的产品行为不得偷偷采用某个方案；已授权的常规实现细节不需要重复征求确认。

## 4. 需求详情与验收条件

### R06 — 对局控制栏与游戏操作分组

**用户澄清后的要求：** 撤销、重做、重置是一组，放在左上角设置按钮右侧；上下左右等游戏专用操作是另一组，仍留在左下角。

**状态：已完成（2026-10-05，按澄清补正）。** 前一版误将两组一起移到左上角。本轮让原撤销／重做／重置按钮留在设置旁，作为「对局控制栏」；左下角入口称为「游戏操作」，用于方向键、围棋等游戏专用功能。设置中的对应开关改为「显示对局控制栏」。不增加第三组操作或新图标。

验收条件：

- 游戏中，设置入口和对局控制栏在左上区域相邻排列；游戏操作入口保持左下。
- 撤销、重做等原有功能可用；推箱子方向控件和其他游戏专用操作仍可访问。
- 普通窗口、窄屏、全屏下不相互遮挡，不把控件挤出游戏框。
- 不同时重设计按钮图标、配色、棋盘或游戏规则。

左下角保留原有展开／收起方式，面板向上展开、内部滚动；没有可用游戏专用控件时隐藏入口。撤销、重做、重置不再混入这个面板。

### R07 — 控件与间距统一

**用户要求：** 菜单与设置不再出现明显不一致的按钮大小、行间距。

**状态：已完成（2026-10-05）。** 使用 `css/ramified_minigames_player.css` 中的 CSS 变量统一现有控件，保留既有按钮配色及方向键排列，不要求用途不同的控件全部相同。

后续补修：`.player-page .card-body` 的 `display: block !important` 覆盖了联机面板原来的网格，导致两组按钮之间没有行间距。对 `.online-play-panel` 恢复网格和 12px 间距，并移除该面板表单行的重复外边距；按钮组内部间距为 8px。

| 类型 | 当前规则 | 适用范围 |
| --- | --- | --- |
| 主菜单按钮 | 最大宽度 300px、最小高度 44px，垂直间隔 12px | 开始／继续／设置，游戏中菜单 |
| 普通文字按钮、快捷键按钮 | 最小高度 40px，内边距 8px 14px；文字可换行 | 返回、开始、设置页操作、游戏操作、快捷键绑定 |
| 图标按钮及操作入口 | 设置、撤销、重做、重开、关闭等图标按钮为 42×42px；操作入口最小高度 42px | 游戏左上角、操作面板、设置标题栏 |
| 表单控件与标签页按钮 | 最小高度 40px；文字／数字输入和下拉框内边距 8px | 选游戏、显示、联机、导入导出、设置 |
| 表单行与控件间距 | 行间与标签间距 12px，紧凑按钮组间距 8px；设置开关行最小高度 58px | 菜单内表单、设置、操作面板 |
| 标题与页面留白 | 黑底白字；标题栏最小高度桌面 77px、窄屏 70px；页面内边距桌面 24px、窄屏 16px | 主菜单、游戏菜单、选游戏及其他内容页、设置 |
| 状态 | 禁用控件透明度 0.48；键盘焦点为 2px 强调色轮廓、偏移 3px | 玩家页面按钮、表单及菜单入口；开关保留原有可见焦点轨道 |

长内容仍在完整页面内部滚动。设置底部按钮允许换行；窄屏快捷键设置改为上下排列。控件高度是最小值，长文本可以撑高，不能为了齐高而裁掉文字。

验收条件：

- 记录每类控件的尺寸、内边距、间距和适用页面，避免每页重复写不同数值。
- 同类按钮的正常、禁用、键盘焦点状态一致。
- 主菜单、游戏菜单、选游戏／选关、设置的标题区与内容留白有一致规则。
- 中英文长文本、窄屏和内部滚动不会导致按钮文字截断或控件重叠。
- 不借此改变 R02—R05 已确定的设计。

这些规则只作用于玩家入口，不影响 archive 页面或其他计算器页面。R10 的选关页尚未实现，本轮没有把统一样式误记成选关功能已完成。

### R08 — 简化开始游戏

**用户要求：** 开始游玩不应依赖多次配置。

验收条件：

- 按 D01 确定的入口流程进入游戏，不增加流程之外的确认或参数页面。
- 新玩家不必理解「预设」、棋盘几何、调试参数等开发概念。
- 五子棋进入同一个准备页，左右切换棋盘并显示预览，黑白双方分别选择人类／AI，完成选择后再开始；不拆成多个必经配置页面。
- 首次进入五子棋准备页时，黑方预选人类、白方预选 AI—挑战，双方仍可独立修改；现有 AI—激进型选项保留。
- 首次预览棋盘和按默认选择开始的新局均为 boundary glue board、open/classic、15×15；实现时显式指定开放边界，不能沿用源预设的 torus。其他棋盘仍可左右切换。
- 准备页保留尺寸与边界类型设置，沿用原有适用范围；修改后预览同步更新，实际开局与预览一致。
- 详细参数从“更多”完整页面进入；返回时保留参数及焦点，不能挤动准备页的预览或底部按钮。
- 准备页的预选项必须明确，不能为了减少点击而随意改变玩法；其他对局类的启动流程逐款确定。
- 推箱子的启动与 R10 选关流程衔接。
- 返回、取消、已有进度下开始新游戏的行为清楚，不意外覆盖玩家进度。

**状态：部分完成（2026-10-06）。** 五子棋已使用独立准备页；其他游戏仍保留原配置页，因此不把 R08 整体标为完成。

2026-10-05 已整理 [R08 开始流程设计讨论](ramified_R08_start_flow.md)，包括当前默认棋盘、三个优先决策、建议状态流程和分批实施 prompt。

2026-10-06 用户确认上述五子棋流程和默认配置，并决定整个游戏集保留一份进度、直接实施。本轮完成共用游戏列表与五子棋准备页；切换棋盘保留双方选择，开局采用预览中的棋盘。浏览时保留旧棋局、撤销／重做与旧存档；仅在正式开局前确认一次替换，取消确认回到准备页。失败和迟到的加载结果不会覆盖原局。其他游戏的专用流程仍待后续讨论。

2026-10-07 补正：已修复切回边界粘合棋盘后尺寸变为 4 的错误，同次准备中的自定义尺寸、形状和边界均保留。用户随后授权调整排版，“更多”、预览两侧箭头、下方双方选择与右下角开始按钮均已实现并通过浏览器检查，见 [布局实施记录](ramified_R08_start_flow.md#6-五子棋布局2026-10-07已实现)。R08 仍为部分完成。

### R09 — 继续游戏启用条件

**用户反馈：** 开局时继续游戏没有禁用。

代码核对结果：

- 当前条件是引擎已就绪、没有正在恢复，并且存在 `state.active`、`saved` 或在线房间中的任意一个。
- 初次读取本地存档时，只检查了 `version === 1` 和 `payload` 是否存在；这不等于确认存档可恢复。
- 此前浏览器测试会留下测试棋局。它是需要排查的可能因素，尚未证明是用户反馈的原因。

使用隔离的测试存档或测试环境核查，不清空用户真实进度：

| 场景 | 验收预期 |
| --- | --- |
| 首次进入，没有存档、没有进行中的游戏 | 继续游戏禁用。 |
| 只初始化默认棋盘，或只查看配置／关卡 | 不应因此出现可继续的进度。 |
| 存在进行中的本地游戏，返回主菜单 | 继续游戏可用，并回到同一棋局。 |
| 刷新后存在有效本地存档 | 继续游戏可用，并正确恢复。 |
| 存档损坏、版本不支持或无法恢复 | 不把它当成可用进度；给出必要且简短的反馈，不反复启用一个必定失败的入口。 |
| 存档正在加载／恢复 | 禁止重复触发恢复。 |

2026-10-06 配合 R08 已在独立浏览器确认：首次无存档时继续禁用，浏览五子棋准备页不生成存档，有效新存档可刷新恢复。无效存档、已结束棋局与真实联网会话仍未完整验收，本条不因这些局部验证而关闭。

已结束棋局是否仍可继续、联网房间中的「继续」具体表示什么，见 D04。先复现、定位，再判断需要修代码还是纠正测试环境；不能先把此项标为已修复。

### R10 — 推箱子选关

**用户要求：** 关卡类游戏采用适合关卡的流程，推箱子可提供选关界面。

验收条件：

- 选择推箱子后进入玩家能理解的关卡选择流程。
- 选择关卡后直接进入该关卡，不再经过通用对局配置页。
- 回到选关和回到主菜单的行为明确，不混淆关卡选择与正在进行的关卡。
- 棋盘、推箱子规则、方向控件和撤销功能沿用现有实现。
- 中英文关卡名称可用，长列表在固定游戏框内滚动。

关卡顺序、是否全部开放等见 D02。星级、奖励、解锁、自动进入下一关等都不在已经确定的需求中，不自动新增。

### R11 — 玩家信息精简

**用户要求：** 玩家菜单不再堆放开发功能、内部统计和长段实现说明。

验收条件：

- 玩家主流程中不再出现导入／导出、独立的内部统计页面及旧版／调试链接；调试功能仍可从独立旧版地址使用。
- 设置中移除长段存档实现说明，必要的保存／恢复错误仍有简短反馈。
- 检查错误提示、帮助与键盘入口，不能删除按钮后仍引导玩家寻找已不存在的菜单。
- 区分独立的统计页面与棋盘上帮助游玩的分数、步数等信息；不顺便删除后者。
- 统计采集与告知按 D03 一起处理，不将「删掉说明文字」误记成「停止采集」。

玩家菜单最终保留哪些入口，应先列清单再修改。不把移除的入口重新集中到另一个面向玩家的「高级」大面板。

### R15 — 默认 R 键重新开始

**用户要求：** 有些游戏缺少 R 键重置，可以视情况作为默认。
