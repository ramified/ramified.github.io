# R17：全游戏集三个存档

更新日期：2026-10-10。实施分支：`ramified_menu`。

**状态：已实现并验收。** 用户已确认：全游戏集共用三档，每档进度独立；重开清除该档棋局和推箱子记录，从前三关重新开始，其他档不受影响。

## 1. 已实施的范围

每档保存一局当前游戏，以及该档独立的推箱子完成／解锁记录。三档共用于整个游戏集，不是每款游戏各有三档。

| 操作 | 行为 |
| --- | --- |
| 开始游戏 | 游戏列表 → 选择游戏 → 选择存档 → 原准备页或推箱子数字选关。浏览不会创建空存档。 |
| 继续游戏 | 显示三个存档；空档禁用。有棋局则恢复，无棋局但有进度的档进入游戏列表。 |
| 在已有档开始另一局 | 正式开局前沿用替换确认；只替换选中档的棋局，保留该档推箱子进度。 |
| 重开存档 | 明确显示目标编号及清除范围，默认焦点在“取消”；确认后清空该档棋局和完成记录、恢复前三关，随后选择游戏。若已选好游戏，则返回该游戏的准备／选关页。 |
| 删除存档 | 同样需要确认；该位置变为空档，其他档不变。 |
| R 键或原对局重置 | 沿用原规则，只重新开始当前棋局，不等于重开整档。 |
| 切换或刷新 | 恢复棋局、AI 控制者及存档中的显示设置。切到其他档后不保留前一档的撤销栈；只在菜单内往返或取消准备仍保留原局撤销。 |

固定外框、黑底白字标题、原棋盘和控件保留。选档页沿用按钮样式，桌面／全屏内容水平居中，窄屏页面内部滚动。没有新增存档命名、美术、奖励或玩法。

R18（Menu / Main menu 的重复层级）和 R19（Online Play 流程）仅登记，均未重设计。联网房间仍不作为本地存档。

## 2. 数据与迁移

`js/ramified_minigames_save_slots.js` 管理三档容器，键为 `ramified.minigames.player.slots.v1`：

```text
version: 1
slots: [null 或 {game, sokoban}, null 或 {game, sokoban}, null 或 {game, sokoban}]
```

- `null` 表示空档。重开后是已有档，但 `game` 为空，推箱子仅开放前三关。
- `game` 继续使用原来的版本 1 棋局快照；不改每款游戏的状态格式。
- `sokoban` 复用按稳定关卡 ID 去重和逐关解锁的规则。
- 旧单份棋局和旧推箱子进度自动迁入存档 1；只有旧进度也能迁移。原两个键保留为备份。
- 三档容器一旦存在，就不重新导入旧备份，避免删除后数据重新出现。
- 每次以一次 `localStorage.setItem` 写入整个三档容器，棋局和通关记录一并提交。
- 写入失败时，自动保存保留本标签页内的进度，并显示简短错误；删除／重开必须写入成功才更新内存。无法读取或版本未知的数据保留原始内容，不用空容器覆盖。

正在游玩的档与准备新局的目标档分别管理。保存计时器绑定正在游玩的档；删除／重开会取消待保存任务。准备、取消和失败不提前写入目标档，恢复接口的取消检查防止迟到响应替换已退出的页面或棋局。取消其他档的准备后回到原游戏，“下一关”继续使用原档，避免串档。

## 3. 本轮顺带修复的必要问题

分档恢复测试发现，原恢复接口没有将快照的显示设置传给导入逻辑；从推箱子切到五子棋时可能沿用格心显示。现在恢复已保存的显示方式、棋子大小等设置，保留原画法。损坏的控制者数组也在修改当前棋局前验证。

推箱子目录在用户此前的 `c74b5e7` 提交中已调整顺序，本轮保留该目录，将旧测试与文档的顺序同步。没有再次改变关卡文件或排序。
