# R08：开始游戏流程的设计讨论

日期：2026-10-05。状态：**分析建议，尚未实施**。

对应 [需求跟踪文档](ramified_player_requirements.md) 的 R08，涉及 R09 的继续与存档、R10 的选关。本文中的推荐方案需要用户确定后才实现，不授权顺便更改玩法、棋盘、AI 或存档范围。

## 1. 先确定玩家要完成什么

玩家点击「开始游戏」，想得到的是一局可以操作的游戏。当前页面要求玩家先理解游戏、预设、显示方式、控制者和各种参数，原来面向试验的设置步骤仍在玩家路径中。

需要先回答三个问题：

1. 玩家这次想玩哪种游戏？这是游戏集通常需要保留的选择。
2. 选择这款游戏后，还必须知道什么才能开始？推箱子需要关卡；对战游戏需要明确由谁控制双方。
3. 其他项目能否提供合适默认值，在有需要时再调整？音量、按键、显示偏好不应成为每次开局的必经步骤。

KISS 在这里可以作为一条检查规则：**每个开局前的必选项，都应能说明“为什么没有它就不能正确开始”。** 如果解释不出来，应考虑默认值或可选入口。

棋盘与边界变化是这个项目的重要内容。简化入口时仍应保留玩家选择棋盘的能力，具体放在哪里需要确定。

## 2. 当前实现有哪些基础

| 已有能力 | 对 R08 的意义 |
| --- | --- |
| `ramified_minigame_presets/presets.js` 已给 11 种游戏指定默认棋盘 | 可以从既有默认值开始讨论，不必重新发明一套配置。现有默认值仍需由作者判断是否适合初次玩家。 |
| 玩家入口已有独立页面、开始、继续、返回、设置 | R08 可以复用这些外框与导航，保持已确定的 UI。 |
| 引擎已有加载预设、生成开局、开始游戏的函数 | 可以调整入口流程，同时复用规则和棋盘渲染。 |
| 五子棋、四子棋、中国跳棋已有本地 AI 配置 | 可以讨论这些游戏默认人机还是同机多人；其他游戏不能凭菜单文案就假定已有 AI。 |
| 本地只有一个总存档槽 | 开始另一款游戏会涉及覆盖当前进度，不是每个游戏分别自动保留一份。 |
| 推箱子目前仍按「预设」选择；国际象棋类也含不同用途的棋盘 | 需要区分规则类别、普通棋盘与解谜关卡，不能只按引擎名字机械分类。 |

当前还存在一处流程耦合：进入新游戏准备时，`prepareNewGame()` 会调用 `engine.prepare()`，使当前棋局进入准备状态。因此，“浏览候选游戏后取消，回到原棋局”不能只靠换按钮文字实现；需要在正式开局前保留当前棋局。

## 3. 现在最值得先决定的三件事

### A. 「开始游戏」进入哪一条路径？

| 选择 | 玩家路径 | 适用情况 |
| --- | --- | --- |
| **建议：先选游戏，再进入可玩的内容** | 主菜单 → 选游戏 → 默认开局；关卡游戏转到选关 | 维持游戏集的含义，入口容易理解。 |
| 先选游戏，再统一选择棋盘 | 主菜单 → 选游戏 → 选棋盘／关卡 → 开局 | 希望玩家每次都主动选择边界或地图，愿意多保留一步。 |
| 直接开始某一款游戏 | 主菜单 → 指定游戏的默认开局 | 需要明确指定默认游戏，并另设切换游戏入口；单凭「开始游戏」无法表达它会启动哪款。 |

我的建议是第一种：选定普通游戏后使用已批准的默认开局；想换棋盘时再进入可选的棋盘选择。推箱子的关卡选择属于核心内容，可以保留为必经步骤。

这里需要你决定的是：**棋盘选择是每次必经，还是提供默认开局、另留可选入口？** 暂时不用决定选游戏页面的图案、排版或装饰。

### B. 对战类默认让谁来操作？

“自动开始”只有在控制者明确时才有意义。两边都由玩家控制、单人与 AI 对战、联网对战，是不同的游玩场景。

| 选择 | 影响 |
| --- | --- |
| 保留现有同机人工控制默认值 | 改动较小，但独自打开页面的人可能不明白为什么轮到自己操作另一方。 |
| 对已有 AI 的游戏默认人机 | 适合独自试玩；需要确定玩家阵营、先手、AI 风格等默认值。未实现 AI 的游戏仍要明确是同机多人。 |
| 对战游戏开局前选一次模式 | 多一步，但玩家知道自己将与谁对战；只显示该游戏真正支持的选项。 |

建议：把「对战方式」视为可能需要保留的一项选择，而不是把所有对战参数继续放回开局表单。若你希望单人试玩尽量快，可以只为已有 AI 的游戏批准默认人机方案。

本轮不建议为了统一入口给所有游戏新做 AI；这应是单独的玩法工程。

### C. 浏览新游戏和替换旧进度，分别何时发生？

建议规则：

- 点击开始、浏览游戏或关卡时，保留原来的进行中棋局和存档。
- 只有玩家选定内容并准备正式开局时，才处理旧进度。
- 没有可恢复进度时直接开始；存在需要覆盖的进度时，只确认一次。
- 取消选择、返回上一级、加载失败，都应仍能继续原棋局。

需要你决定的是：第一版是否继续使用一个总存档槽。**建议先保留一个槽，完善替换时机和取消行为。** 按游戏分别保存、多存档槽会扩大 R08 的范围，可以另行规划。

确认覆盖属于保护旧进度的必要反馈，不应在同一条启动路径里重复出现。已完成棋局是否仍要确认覆盖，与跟踪文档 D04 一起决定。

## 4. 为每款游戏写一行“默认开局”

下面列的是代码当前默认值，**不是对新手友好程度的背书，也不是新的默认方案**。这是接下来与作者一起填的表。

| 游戏 | 当前默认棋盘 ID | 需要作者确认的开局含义 |
| --- | --- | --- |
| Hex | `classic-hex` | 同机双人还是保留模式选择；规则选项采用哪个默认值。 |
| 五子棋 | `wormhole` | 棋盘是否适合第一局；同机双人或已有本地 AI。 |
| 围棋 | `gomoku-big-hole` | 默认棋盘、贴目、计分方法；同机双方控制是否清楚。 |
| 四子棋 | `connect-four-exchange` | 默认落子方向、入口孔和对手；开局不能要求玩家先编辑入口孔。 |
| 2048 | `ramified-cover` | 是否作为默认试玩棋盘；其他棋盘何时可选择。 |
| 黑白棋 | `focus-frame` | 默认棋盘与同机双人流程。 |
| 中国跳棋 | `octahedron-with-square-holes` | 默认参与阵营、人数、控制者和跳跃规则。 |
| 推箱子 | `classic-fans` | 哪些预设算正式关卡、显示名称和顺序；与 R10 合并确定。 |
| 国际象棋类 | `fide-chess-8x8` | 普通对局与皇后等解谜内容如何区分入口。 |
| 台球 | `half-glued` | 默认自由练习还是某套对局规则；提供可直接击球的球桌。 |
| 连连看 | `rubiks-cube-3x3x3` | 默认棋盘、牌面集及级别；是否要让新玩家先选择。 |

建议先批准一到两款游戏的默认开局，例如一款单人游戏和一款对战游戏，用它们检验流程。其余游戏仍应保留原入口，不能在第一批改动中被悄悄隐藏或采用未批准的默认值。

## 5. 内容应放在哪一层

| 内容类型 | 建议位置 | 原因 |
| --- | --- | --- |
| 玩哪种游戏 | 选游戏页 | 决定本次游玩内容。 |
| 哪个关卡 | 选关页 | 是解谜游戏的内容选择。 |
| 与谁对战 | 需要时在开局前选择，或采用作者批准的明确默认值 | 直接影响玩家接下来如何操作。 |
| 棋盘变体、可变规则 | 可选的新对局配置；是否保留必选由 A 决定 | 应在新局生成前确定，不能在进行中的棋局里悄悄替换。 |
| 音量、按键、显示偏好 | 设置 | 应可在游玩中调整，通常可记住偏好。 |
| 预设编辑、调试参数、开发统计 | archive／debug | 不应成为普通玩家开局的前置知识。具体移除入口仍由 R11 处理。 |

「暂时不展示」不等于删除底层能力。先确定玩家入口需要哪些选项，再决定哪些功能留给调试页，避免用隐藏控件掩盖默认值未定义的问题。

## 6. 实现时先写行为，再画页面

以下是建议的状态关系，尚未实施：

```text
主菜单
  └─ 选择游戏（原棋局仍保留）
       ├─ 普通游戏：取得已批准的默认开局
       ├─ 关卡游戏：选择关卡
       └─ 可选配置：只在玩家主动要求时进入
              ↓
       已确定本次开局内容
              ↓
       如需覆盖旧进度，确认一次
              ↓
       加载并校验成功 → 开始新局
       取消或失败     → 保留原棋局，可返回继续
```

建议将“正在浏览的选择”和“实际进行中的棋局”分别保存。选择页只修改待开始的游戏／棋盘／控制者，不提前调用会重置当前棋局的准备函数。加载与校验完成后再应用新局，存档也在成功开局后更新。

这会让取消、加载失败和继续游戏的行为更容易测试。它是 R08 与 R09 的连接点，应明确写入验收条件。

## 7. 分批解决，不一次重写所有游戏

1. **先确定 A、B、C。** 用一句话分别说清开始路径、对战方式和旧进度处理。
2. **批准首批游戏的默认开局表。** 对其他游戏暂缓，列出不改变的旧流程；不要推断作者偏好。
3. **先完成一条可操作的启动路径。** 复用固定外框、菜单样式、棋盘和引擎，验证开始、返回、取消、失败和继续。
4. **把同样的状态管理应用到其他已批准游戏。** 每款只补内容配置或必要的模式选择。
5. **推箱子与 R10 协同实施。** 先明确关卡清单，再做选关；不顺便增加星级、奖励或解锁系统。

首批验收至少包括：

- 首次进入，能按已确定路径开始，过程中没有需要玩家理解的开发参数。
- 打开选择页后取消，可以继续同一棋局，撤销记录仍在。
- 加载或校验失败，不覆盖原棋局与存档。
- 正式开始后，控制者、棋盘、规则与批准的默认开局表一致。
- 没有旧进度时没有多余确认，有需覆盖的进度时只确认一次。
- 未纳入首批的游戏仍可进入；中英文、窄屏和全屏可用。

## 8. 你可以怎样写下一条 prompt

先讨论决策时，不必提供完整技术方案：

```text
请继续讨论 implement_plan/ramified_R08_start_flow.md，不修改代码。
A：我希望开始游戏后……；棋盘选择应该……。
B：我主要想让玩家单人试玩／同机多人／两者都能方便进入。
C：第一版保留一个总存档槽／我需要分别保留各游戏进度。
请据此帮我填写首批游戏的默认开局表，并指出仍有歧义的地方。
暂时不确定的项目请保留为待决定，不要自行补完。
```

决策明确后再授权实现：

```text
请按已经确认的 R08 流程，只实现 [首批游戏列表]。
默认棋盘、控制者和规则采用 [已确认的表格]。
浏览、取消和加载失败时保留原棋局；正式开局成功后再更新存档。
其余游戏的入口继续保留。不要新增玩法、美术、宣传文案或存档槽。
在 ramified_menu 分支完成验证，并更新需求跟踪文档。
```

当前最先需要决定的是 A。它会决定是否需要一个独立的棋盘选择步骤；确定后再讨论 B、C 和各款游戏的默认值，不需要一次把整份表全部填完。
