## 1. 已确认并实施的玩家流程

```text
主菜单 → 开始游戏 → 游戏列表 → 五子棋／四子棋准备页 → 开始对局
```

游戏列表已接入用户提供的 11 张游戏图片（R16），图片在上、原中英文名称在下，整项作为同一个按钮进入对应游戏；每页 2 行 × 3 列，左右箭头翻页；图片占据格子主要空间。准备页返回及语言切换保留原页，重新点击开始／更换游戏回到第一页。

五子棋准备页在同一个完整页面内提供：

- 原棋盘渲染生成的预览，切换按钮置于预览两侧，名称在下方。
- 黑白棋子标识下并排选择控制者，左右切换人类、AI—挑战、AI—激进型。
- 左下“更多”打开完整参数页，保留棋盘尺寸、边界类型和形状设置，按原有适用范围显示。
- 右下开始游戏；准备页顶部返回按钮回到游戏列表，参数页顶部返回则回到准备页。

双方左右按钮修改原控制者选择框的值并触发其原有事件，没有增加第二级 AI 菜单或另一套 AI 配置。固定 4:3 外框、黑底白字标题、原棋盘画法和游戏控件均保留。窄屏下内容内部滚动，底部的“更多”和“开始游戏”持续可见；浏览器全屏可用。

### 五子棋默认配置

| 项目 | 已确认的值 |
| --- | --- |
| 棋盘 | boundary glue board（`boundary-glue-board`） |
| 边界 | open/classic（`open`） |
| 尺寸 | 15×15，正方形 |
| 黑方 | 人类 |
| 白方 | AI—挑战 |

每次从游戏列表建立新的五子棋准备页时使用这套配置；在该准备页内修改控制者后，左右切换棋盘不会把控制者重置为人类。取消覆盖确认会回到同一准备页，保留刚才的选择。没有新增跨刷新记住准备页偏好的系统。

2026-10-07 修复：同一次准备过程中，切走再切回棋盘会恢复该棋盘已选的尺寸、形状和边界；默认 15×15 不再变为 4×4，自定义正方形及长方形行列数也保留。原因是原切换处理重新套用了源预设的 4×4 尺寸。参数仅保留在本次准备中，不改变源预设或 archive 默认值。

改变尺寸、形状或边界后，预览随之更新；正式开始使用预览中的棋盘。随机边界也沿用该次预览结果，不在按下开始时重新抽取。

这套默认值只应用于五子棋玩家入口。共用预设目录和 archive 的默认配置没有改成五子棋的默认配置。

## 2. 已确认并实施的进度规则

用户决定：**整个游戏集保留一份当前进度。**

| 玩家动作 | 结果 |
| --- | --- |
| 打开游戏列表 | 原棋局与存档保留。 |
| 进入准备页、换棋盘或调整参数 | 只改变待开始的新局，原棋局和撤销／重做记录保留在内存中。 |
| 从准备页返回 | 返回游戏列表；随后可以回主菜单继续原棋局。 |
| 没有旧进度，点击开始 | 直接开局。 |
| 有旧进度，点击开始 | 显示一次替换确认；此前不覆盖旧存档。 |
| 取消替换确认 | 回到准备页，保留当前选择和旧进度。 |
| 确认且新局成功开始 | 新局成为唯一的当前进度，按原有方式自动保存。 |
| 棋盘加载失败、取消后加载才完成 | 保留原棋局与存档，不用迟到的结果重置原局；可以返回或重试。 |
| 刷新后继续 | 恢复已保存的棋局和 AI 控制者；沿用原有不恢复撤销记录的规则。 |

仍使用 `ramified.minigames.player.save.v1` 这一份本地存档，不新增按游戏分开的存档，也不保存真实联网房间。浏览设置过程中没有迁移或清空用户的旧存档。

## 3. 实现与核对要点

- `js/ramified_minigames_player.js` 负责游戏列表、准备页、返回和确认流程；迁移原控件时保留其事件监听器。
- `RamifiedMinigames.player.beginSetup / cancelSetup / commitSetup` 管理待开始的新局。旧棋局对象、撤销／重做栈和相关控件值先保留，取消时恢复；正式开局成功后才释放。
- 新预览画布复制原引擎的渲染结果，不另画一套棋盘。只读预览不允许落子或启动 AI。
- 切换配置需要等待当前一步操作稳定完成；打开玩家菜单时仍按原逻辑暂停 AI 的下一步。
- `boundary-glue-board` 源预设原本默认 torus，所以玩家五子棋开局显式设置 `open`、15 行、15 列。检查结果为无粘合边的 15×15 棋盘。
- 预设异步加载使用序号检查，返回后到达的加载结果不会覆盖恢复的原棋局。
- 新增与直接修改的界面文本使用英文／简体中文词条，并更新资源缓存版本。

四子棋现已采用同一准备页结构，具体默认值与方向保留规则见第 8 节。其余九款游戏仍从游戏列表进入原有配置页，同样使用新局确认与取消保护；没有推断其新的 AI、棋盘或关卡设计。

用户提出：详细参数收进“更多”，切换按钮放在预览左右，棋盘名称放在预览下方，黑白双方并排置于名称下方，开始按钮在右下角。

- 棋盘箭头与预览垂直居中，两侧宽度固定；名称换行时不改变预览大小。
- 双方控件等宽，同一行对齐；保留人类、AI—挑战、AI—激进型，默认值不变。棋子仅用于辨认黑白方，配合文字／无障碍标签。

## 7. 准备页推广：决策说明与填写模板

**状态：四子棋已由用户确认并实施，其余游戏仍为建议。** 以下模板继续用于逐款推广；未确认的建议不作为默认值，不改变 R10、R11 的完成状态。

### 7.1 怎样拆分这次工作

从玩家的角度，一张准备页需要说清楚三个问题：这局玩什么、谁来玩、按开始后进入什么状态。共用布局负责把这些选择放在稳定的位置；各游戏只补充自己的选项。

已确认的公共部分可以继续沿用，无需每款重新设计：

- 固定 4:3 外框、完整页面、黑底白字标题、现有按钮和间距规范。
- 预览两侧切换棋盘，名称在预览下方；使用原棋盘渲染。
- 左下“更多”、右下“开始游戏”；更多是可选步骤，打开和返回均保留选择。
- 返回游戏列表时保留所在分页；浏览准备页不覆盖旧棋局，正式开局沿用单份进度替换确认。
- 中英文、键盘、窄屏和浏览器全屏均作为验收范围。

以下是推广建议，需要按游戏确认：

- 有可选控制者时，在预览下方显示玩家选择；单人游戏省去这一行。
- 只有固定人类玩家时，建议省去不可修改的选择器。是否保留双方标识可以作为单款例外说明。
- 同一次准备中切走再切回棋盘，应保留该棋盘刚才的参数；跨棋盘的规则冲突由实现时列出可行处理方式，不能强行套用无效数值。
- 每次新进入准备页，建议恢复该游戏确认过的默认值，和五子棋一致。若希望跨会话记住上次选择，应单独说明；“默认值”和“记住上次”是两种不同的行为。

### 7.3 决定一个选项放在哪里

| 玩家什么时候需要它 | 建议位置 | 当前项目中的例子 |
| --- | --- | --- |
| 每次开局主要在选什么、和谁玩 | 准备页直接显示 | 棋盘预览、已有的人类／AI 选择；连连看字符类别是否属于此项由用户决定。 |
| 偶尔调整这一局的规则或棋盘参数 | 更多 | 适用棋盘的边界、形状、行列数；四子棋下落方向、围棋贴目。 |
| 调整观看和操作习惯 | 现有设置中的对应位置 | 坐标、棋子大小、动画速度。迁移前核对原入口，不能导致功能丢失。 |
| 这局开始之后才有意义 | 游戏中的原操作区域 | 围棋停一手、跳棋结束跳跃、推箱子方向键。 |
| 用来测试和观察实现 | 调试入口，按 R11 另行处理 | 调试输出、研究遥测。此文档没有执行 R11 清理。 |

“主页面不显示”需要同时说明保留入口。把一项收进更多、移动到设置、移出玩家版，是不同的改动。

### 7.4 用户需要提供的最少信息

| 要回答的事 | 可以怎样填写 | 会影响什么 |
| --- | --- | --- |
| 本轮处理哪些游戏 | “先只做四子棋” | 防止一轮改动过多，便于检查。 |
| 点进游戏后先看到什么 | “直接进入和五子棋类似的准备页”或“先选关” | 页面流程与返回路径。 |
| 不改任何选项，应该开出哪一局 | 棋盘名称、适用尺寸、玩家／AI 或参与阵营 | 第一次点击开始时的体验。可用界面名称，不必填写代码 ID。 |
| 哪些选项必须直接看到 | “棋盘、红黄双方”或“棋盘、字符类别” | 主页面的内容和留白。 |
| 哪些选项进更多 | 写选项名称，或“请先列出现有开局选项供我挑选” | 精简页面但保留选择能力。 |
| 哪些例外需要保留 | “其他棋盘都保留”“暂不处理联网”“不动对局中的设置” | 明确本轮边界。 |

不需要用户提供 DOM、CSS 尺寸、函数名或测试代码。这些由实现者处理。每项都可以写“待决定”；实现者先列出现状和一两种有依据的建议，其他已确定部分继续推进。
