# R19：联网大厅与房间流程设计

更新：2026-10-12。分支：`ramified_menu`。

**状态：A—F 及衔接规则已实现，本地自动化与双浏览器验收完成；线上 Cloudflare 部署及部署后的跨设备复验未执行。** 用户已明确接受第 10.1 节全部建议并授权实现，没有剩余产品选项需要重复确认。R18 完整菜单层级和 itch.io 发行不在本轮范围。

## 1. 目标与范围

- 主菜单独立“在线游戏”，进入游戏框内的完整大厅，不先选本地存档。
- 大厅展示游戏集的所有在线浏览器身份及房间，房间列出游戏、房主、成员、已占／可用席位、状态和计时规则。
- 建房从多人游戏列表和初始棋盘准备开始，不把当前本地残局带入房间。
- 保留原固定 4:3 外框、黑底白字标题、棋盘、操作控件、2×3 游戏分页、显示设置、语言和全屏入口，不新增美术、AI、聊天或账号系统。

## 2. 页面职责与返回

| 页面 | 主要行为 | 返回／退出 |
| --- | --- | --- |
| 主菜单 | 本地开始与在线游戏独立 | 本地先选档流程保持原样 |
| 联网大厅 | 在线名单、房间列表、昵称、刷新、创建／加入 | 返回主菜单；失败可重试 |
| 多人游戏列表 | 按现有顺序过滤八款游戏 | 取消创建回大厅；取消房主修改回原房间 |
| 准备页／更多 | 沿用棋盘预览与参数；“更多”包含时限 | 同次草稿保留；正式提交前不改原房间 |
| 房间 | 选席、准备、成员状态、提案、查看棋盘、退出 | 查看棋盘不退房；明确退出回大厅 |

房间和大厅使用完整页面，阅读区域居中，内容内部滚动，页脚稳定；不重新引入独立小卡片。窄屏保留 4:3，因此需要滚动房间内容。加载失败保留重试／返回，迟到响应不能覆盖已退出的页面。

## 3. 在线身份与房间目录

在线范围包括主菜单、本地游戏、大厅、各房间棋手及观战者，也包括自己。页面级 WebSocket 会话以现有 clientId 去重；同一浏览器多标签页合为一人，不按昵称合并不同浏览器。未命名者沿用自动昵称，后台页面只要连接有效仍算在线。

房间服务是成员与棋局的依据，目录用于发现房间；过期目录加入失败后可以刷新。列表更新和清理不能覆盖棋钟／断线宽限的闹钟。匿名访问统计保留原实现，不混用在线名单与分析数据。

## 5. 成员、席位、开局与房主

创建者默认第一阵营，其他新加入者先观战，再明确选择空席；打开房间不能自动接管残局。双人游戏每人一席；跳棋保留一人多阵营，但开局必须至少两名不同真人、全部启用阵营有控制者、所有棋手准备。观战者不计入准备条件。

房主与阵营独立，以服务端成功加入顺序记录；继任者是剩余在线参赛成员中最早加入者，不按颜色或昵称。宽限内重连保持顺序，正式离席后再加入是新成员，旧房主不自动夺回管理权。房间仅剩观战者时无房主；首位明确成为参赛者的人接任。配置生效后房主身份保留，但所有人需要重新选席。

主动退出立即释放席位。断线保留身份和席位 60 秒，宽限内重连恢复，超过宽限才正式离席。连接为零同时启动独立的 5 分钟空房清理；仍有观战连接则不删除。

部分棋手离席保留棋局，接替者继承席位时钟；在线方在自己的回合仍可行动。所有棋手正式离席则中止本局、不产生赢家；后来加入开始新的等待／准备流程，不能复活已中止的旧局。

## 6. 更改配置与同意

房主从原房间进入同一游戏列表和准备页，完成游戏／棋盘／参数／时限后提交。旧局与棋钟在准备、征询期间继续。提案显示新游戏、棋盘、尺寸、适用规则及计时配置，并说明会开始新局。

- 只征询其他参赛者；观战者可留可走。拒绝者退出房间，同意者留下。
- 60 秒内没有完成同意则取消提案，不将未回应者踢出，不将断线视为同意。
- 正式离席者不再计入同意条件；提案期间新加入者只能观战。
- 房主离席取消提案；改动内容产生新的提案版本，旧回应无效。
- 全部需要的同意到齐才应用；新 roundId、状态版本递增、清空准备并重新选席，正式开局才启动新棋钟。
- 旧局超时不阻止提案作为下一局配置；旧局动作不能覆盖新局。

## 7. 棋钟

默认不限时。房主可选各方总时长、每次完整行动时长、总时长＋3 次读秒；必填秒数为 1—86400 的整数，各席位同值，跳棋按颜色独立。服务端记录剩余时间和裁定，浏览器只显示倒计时。

3 次包含当前周期。总时间用完后，从 3×30 秒独立开始：20 秒落子仍 3 次，40 秒落子剩 2 次，70 秒落子剩 1 次，90 秒仍未完成则超时；完成一手只补满当前周期，不恢复已消耗次数。

完整合法行动才重置每步／当前读秒周期：跳棋连续跳跃中途不重置，国际象棋升变算同一手；围棋停着和 Hex 换色算行动，Hex 换色时剩余时间随玩家交换。跳棋开局中尚可行动的颜色并行计时。

断线、缺席、提案、历史操作征询均不停钟。台球选角度、力度、放母球扣时，服务端计算和确定性运动回放不扣；下一杆开始新的行动时间。围棋终局数子停止棋钟，恢复行棋沿用剩余量。自动动画时长由服务端决定，不采用客户端任意动画时长。撤销／重做不退主时间或次数，也不借反复撤销补满周期。

双人超时结束本局并标记超时方判负；多人跳棋超时结束整局并列出超时方，不给其他人自动排名。已有终局不被迟到计时覆盖。国际象棋沿用现有引擎终局，本轮不扩展 FIDE 6.9 的额外判和例外。

## 8. 本地存档与失败保护

进入联网前保留当前本地棋局、原槽位归属、撤销／重做及准备参数；联网和房主草稿期间不输出可自动保存的本地快照。退出后恢复原局和历史。三档与推箱子记录不变。

引擎依赖延迟加载；切换、离开、旧连接或旧导入响应不得覆盖新页面。加载失败显示重试／返回，不覆盖存档。不同客户端保留自己的显示偏好，房主配置不覆盖个人显示设置。

## 9. 代码与部署边界

- `js/ramified_minigames_online.js`：大厅、房间、席位与提案 UI、在线名单、棋钟显示。
- `js/ramified_minigames_player.js` 与 `setup.js`：复用准备页、独立联网草稿、加载与本地会话恢复。
- `cloudflare/ramified-chess.worker.js`：目录、成员、房主、提案、版本与生命周期。
- `cloudflare/ramified-room-clock.js`：可控时间的棋钟／结束逻辑。
- `cloudflare/ramified-room-billiards.js`：复用原物理引擎的服务端击球与动画时间。

前端和 Worker 必须配套更新。现有 GAME_ROOM 绑定继续使用，不更改本地存档版本；旧房间缺少新字段时兼容补齐，旧 archive 入口保留。Worker 构建包含上述模块及现有台球依赖，不能只把单个 Worker 文件复制到在线编辑器。已验证 esbuild 可生成完整 ESM 包（约 325 KB）。

未执行线上部署或 Cloudflare 真实环境验收。后续发布按 `cloudflare/ramified-chess.wrangler.toml` 构建部署整个 Worker，再发布对应前端，并用两台设备复验跨网络、后台断连和 Durable Object 唤醒；这部分不能用本地测试冒充。

### 10.1 一次确认剩余规则

以下 A—F 及其后衔接规则已于 2026-10-12 **全部获得用户确认**。它们收敛此前讨论，为本轮实现和验收依据，包括各方初始时长相同、暂不扩展国际象棋额外超时裁定。不再逐一询问接口字段、布局像素或计时器代码等技术细节。

| 编号 | 要决定什么 | 建议采用的完整规则 | 对应原条目 |
| --- | --- | --- | --- |
| A | 入口、选席位和开局 | 主菜单增加“在线游戏”，直接进入完整游戏内大厅，不选本地存档。创建者默认第一阵营并可改选，其他人选择空位。至少两位不同参赛者，启用阵营全部有人、所有参赛者准备后自动开局；保留跳棋一人多阵营。 | O04、O07 |
| B | 断线、补位和无房主房间 | 断线保留身份／席位 60 秒，期间不停钟；到期仍未返回则视为离席并释放席位，需要时移交房主。主动退出立即释放。补位者继承该席位当前棋局、剩余时间与读秒次数。只剩观战者时暂无房主，首位明确选择参赛的人接任并组织新局。 | O02、O05、O06、O11 |
| C | 房内修改未回应等边界 | 允许局中提案，草稿编辑和征询期间原局照常进行、照常计时。提案 60 秒未满足同意条件则自动取消，不把未回应者踢出。明确拒绝者仍按已确认规则退出；同意者留下。房主离开则撤销未生效提案。新配置生效后重新选席位、准备并开始新局；改时限也采用这套征询流程。 | O08、O11 |
| D | 计时默认值与计时单位 | 默认不限时；选择计时后由房主填写时长，各方采用相同初始设置。棋钟按阵营／席位独立，一人控制多个阵营时也分别计时。跳棋并行开局阶段对可行动且尚未完成首步的阵营并行计时，随后按原回合顺序计时。 | O07、O09、O11 |
| E | 什么消耗时间、哪些情况恢复时间 | 只计算可由玩家决定的行动时间，正常断线／退出仍遵守已确认的不停钟规则。完整合法行动完成才重置每步时间，浏览或无效点击不重置。游戏动画与围棋终局确认不扣思考时间。撤销／重做不返还时间或读秒次数；只有正式新局重新初始化棋钟。 | O11 |
| F | 超时与结束结果 | 双人游戏超时结束本局、超时方判负；已有合法终局结果不被迟到的计时事件改写。首版国际象棋沿用现有终局判定，暂不扩展额外的超时判和裁定。多人跳棋有人超时则整局结束，标记超时方，不给其他人自动排名。全部棋手退出则中止本局，不产生获胜者。 | O02、O11 |

这里的 60 秒有两个独立用途：B 是断线后保留席位的期限，C 是更改提案等待回应的期限；均不改变用户已确认的“空房间 5 分钟删除”。

为避免“全部按建议”仍留下互相矛盾的细节，上表还包含以下直接衔接规则：

- **B 的重连**：宽限内重连保留原加入顺序。已经正式离席后重新加入按新成员处理，旧房主不自动夺回管理权；接替席位需要明确选择，不能仅凭打开房间就自动接管。
- **B 与棋钟的先后**：在 60 秒身份宽限结束前，棋钟可能已经判超时；超时结果先按 F 生效，宽限不延长思考时间。全部棋手正式退出时停止本局棋钟，但房间仍按观战与空连接规则保留／删除。
- **C 的成员变化**：提案期间新进入者先观战，不能未经回应成为新配置的参赛者。已有参赛者断线时不算同意；恢复后可回应。正式离席者不再列入同意条件。提案取消不强行召回已经选择退出的玩家。
- **C 的席位变化**：新配置生效后重新选择阵营，按服务器接受的有效选位顺序占位，多余成员可留下观战；人数不足时留在等待页。旧棋局结束，新棋钟等正式开局才启动。
- **C 的修改与超时**：修改提案有独立版本；房主改动提案内容须重新征询。旧局正常超时不会被未生效的提案阻止，提案可继续作为下一局的配置；旧局的迟到动作不能影响新局。
- **D 的默认输入**：不把文档中的“10 分钟／30 秒”示例变成固定开局时限；房主选择计时模式后填写必需数值。正整数、单位换算、合理技术上限和错误提示由实现处理。各方同值属于首版产品范围，本轮不包含不对称让时。
- **E 的动作边界**：跳棋连续跳跃和国际象棋升变算完整行动，不能靠中途点击多次重置；围棋停着和 Hex 交换按现有合法动作处理。Hex 换色时剩余时间随对应玩家换到新方，防止把思考用时转嫁给对手。
- **E 的台球与围棋**：台球放置母球、选择角度和力度属于该次击球的决策时间，击球后模拟运动不扣时；能击下一杆时开始新的每步时限。围棋终局数子／确认阶段停止棋钟，恢复行棋后沿用原剩余量。引擎自动结算阶段的时长由服务端规则确定，不能相信客户端随意报告“正在动画”。
- **E 的历史操作**：请求撤销／重做和等待对方回应不停钟，双方同意后仅改变棋局和行棋方，不退回已用的时间／次数；每步或读秒周期的剩余量也不得靠反复撤销刷新。
- **F 的国际象棋范围**：这项明确收敛为“保留现有引擎已支持的终局结果，加通用超时结束”，不宣称本轮实现完整 FIDE 第 6.9 条的所有判和例外。严格比赛裁定及变体棋盘的额外判和规则留待另行设计。
