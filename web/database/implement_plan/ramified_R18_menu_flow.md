## 2. 为什么先选存档

每份存档是玩家的一份独立进度，游戏列表是在这份进度里选择下一项活动。先选档，玩家在挑游戏之前就知道会使用哪份进度，后续准备、选关和开局都属于这一档。

调整前的主菜单先要求区分“开始”或“继续”，之后又要选档；两个入口还承担了不同的选档行为：一个准备新局，一个直接读档。合并后，主菜单只负责进入游戏集；是否继续旧棋局，等明确选中哪一档后再决定。

**合并入口不等于删除继续功能，也不等于每次进入都覆盖旧棋局。** 本方案不把“一档一局”改成“每档每款游戏都保留一局”。同档开启另一局仍会替换当前棋局，推箱子长期进度保留。

## 3. 已确认的主流程：选档后统一进入游戏列表

用户重新比较两种选项后，最终选择统一进入游戏列表；此前“直接恢复”的一次答复已被这次确认取代。

```text
主菜单
  开始游戏 → 选择存档 → 该档的游戏列表
                         ├─ 继续上次游戏 → 恢复该档当前棋局
                         └─ 选择一种游戏 → 原准备页／选关 → 正式开局
  设置 → 原设置页面
```

- 空档、重开后尚未开局的档、只有推箱子进度的档，都进入同一个游戏列表。
- 有可恢复棋局时，游戏列表提供“继续上次游戏”，并标明对应游戏名称。它恢复所选档，而不是后台仍在内存中的另一档。
- 没有棋局时，不显示“继续上次游戏”，保留游戏列表；主菜单的统一入口在加载就绪后可以进入选档，不因三档全空而禁用。
- 点击游戏图片按原规则进入准备／选关。即使点击的是上次玩的同一款游戏，也表示准备另一局；继续旧局由明确的继续操作承担，避免同一图片有两种隐含行为。
- 国际象棋保留“对局／谜题 → 对应准备页”；推箱子保留该档的数字选关和下一关逻辑。
- 游戏列表仍为每页 2 行 × 3 列，保留图片和分页。继续按钮与游戏名位于列表上方并水平居中，不增加“存档详情页”或中间弹窗；窄屏允许页内滚动，保持原外框。

### 已接受的取舍

统一进入游戏列表，使每次选档的结果一致，也能直接选择其他游戏。代价是恢复旧局时需要再点一次“继续上次游戏”。本轮不增加自动恢复、记住最近存档后跳过选档等额外规则。

## 4. 各页面只负责什么

| 页面 | 负责的选择 | 已实现的返回目标 |
| --- | --- | --- |
| 主菜单 | 进入游戏集、打开设置 | 无上一页。 |
| 选择存档 | 选择使用哪一档；沿用重开、删除及确认 | 主菜单。 |
| 游戏列表 | 在选中档内继续旧局，或选择要开的游戏 | 选择存档。返回后可以改选另一档。 |
| 普通准备页 | 选择该游戏的棋盘、玩家及原有选项 | 该档的游戏列表，保留分页位置。 |
| 国际象棋类别页 | 对局或谜题 | 该档的游戏列表。其准备页先返回类别页。 |
| 推箱子选关页 | 选择本档已解锁关卡 | 从游戏列表进入时返回该列表；游戏中“选择关卡”仍返回原游戏中菜单。 |
| 更多参数页 | 修改本次准备的可选参数 | 原准备页，保留本次修改。 |
| 新局替换确认 | 决定是否替换所选档的旧棋局 | 取消返回原准备／选关页，保留选中档及准备参数。 |

游戏中“更换游戏”直接进入当前档的游戏列表，不要求重复选档；从该列表返回选档页才能切换另一档。这样主菜单进入时先选档，已经在某档中游玩时则继续使用明确的当前档。

“返回上一级”和“回主菜单”应有固定含义：前者撤回当前页面的选择，后者离开本地选择流程。设置和游戏中菜单的完整合并／命名问题仍在 R18 后续范围，本文不暗中重排这些按钮。

## 5. 不同存档状态的行为

| 所选档状态 | 已实现的列表行为 | 数据边界 |
| --- | --- | --- |
| 空档 | 游戏列表，无继续操作。 | 选档和浏览不创建存档；首次正式开局才写入。 |
| 有推箱子进度、没有棋局 | 游戏列表，无继续操作；推箱子选关显示该档进度。 | 保留解锁记录，不当作全新空档重置。 |
| 有未完成棋局 | 游戏列表，提供继续；也可以选游戏准备另一局。 | 进入准备页不覆盖旧局；正式开局沿用已有替换确认。 |
| 已结束棋局 | 保留继续入口以查看现有结束画面；推箱子可从结果页进入下一关。 | 沿用目前已实现的恢复能力，不因入口合并清除结果。其他结束／无效状态的完整策略继续跟踪 R09。 |
| 无法恢复的棋局 | 给出简短失败反馈，留在游戏列表，可重试或返回。 | 不把恢复失败自动解释成空档；不静默清除或覆盖。无效内容的完整判定策略仍由 R09 后续核查。 |

重开确认成功后，进入**同一档的游戏列表**；删除确认成功后留在**选档页**，目标位置显示为空。取消两种操作均返回选档页，任何档的数据都不因此改变。

## 6. 已保留的保护

- 选择存档只改变本次导航目标；只有恢复旧局成功或新局成功开局，才把它设为正在游玩的档。
- 选档后选游戏不再询问一次存档；该档贯穿类别、准备、更多、选关及开局确认。
- 仍在内存中的另一档棋局只能保存回原档，不能因玩家正在浏览新档而写入新档。
- 返回选档并换档时，清理上一档尚未提交的准备；退出后的加载结果不能打开旧页面或替换当前棋局。
- 取消新局后恢复原游戏时，推箱子“下一关”和自动保存继续使用原游戏所属档。
- 旧三档数据、迁移备份和每档的棋局格式保持兼容，不因为调整入口再次迁移或清空存档。
- 保留固定 4:3 外框、黑底白字标题、菜单铺满外框、原棋盘和游戏控件；窄屏内部滚动，浏览器全屏正常。
- 新按钮、动态游戏名和无障碍标签同时提供中英文；相关脚本、样式和词条缓存版本已更新。
